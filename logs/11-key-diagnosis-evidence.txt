3. The fatal initramfs hook
---------------------------
/usr/share/initramfs-tools/scripts/init-bottom/udev (initramfs-tools):

    #!/bin/sh -e
    ...
    udevadm settle --timeout=60
    udevadm control --exit

    mount -n -o move /dev "${rootmnt:?}/dev" || mount -n --move /dev "${rootmnt}/dev"
    ...

Because the script runs with `-e`, the `udevadm settle` failure aborts it
before the `mount --move /dev` line. `/root/dev` therefore stays empty.

/init calls:

    run-init -n "${rootmnt}" "${1}"        # validate /sbin/init
    ...
    exec run-init ${drop_caps} "${rootmnt}" "${init}" "$@" \
         <"${rootmnt}/dev/console" >"${rootmnt}/dev/console" 2>&1

Both need ${rootmnt}/dev/console, which only exists after the move.

4. The udev stall
-----------------
Timestamps from /run/udev/data (the initramfs runtime dir, later moved to
/root/run/udev). 293 device records existed; 290 were written within the first
~12 seconds. Only these were late:

    b179:1      (mmcblk0p1, the root SD partition)  ~131 s
    c10:234     (/dev/btrfs-control)                ~121 s
    (the btrfs module is loaded late by the initramfs btrfs scan)

Root was mounted at ~135 s. The queue eventually emptied around 130 s, which
is why every 60 s `udevadm settle` timed out and why the boot took ~4 minutes.
The root device itself is ready at ~3.2 s and the UUID is resolved with
`blkid`, not with udev symlinks, so the initramfs does not need to wait this
long.

    ...

There is no `spin_lock_init(&reboot_lock)` anywhere in the file. The device tree
has `spa,wdt-disabled` but **not** `spa,wdt-enable-restart-handler`, so the
watchdog restart handler is not registered. OpenSBI reports:

    SBI implementation ID=0x1 Version=0x10003    (OpenSBI 1.3)

which predates the 2026 SBI SRST reboot support for K1.

7. SD-card power rails
----------------------
From debugfs regulator_summary:

    dcdc4  ->  d4280000.sdh-vmmc    (SD card VMMC, 3.3 V, dedicated)
    ldo1   ->  d4280000.sdh-vqmmc   (SD card I/O, 1.8 V)
    dcdc3  ->  d4280800.sdh-vqmmc   (the other SDHCI controller)

`dcdc4` is the rail a shutdown hook would have to toggle to power-cycle the
card. Do not touch it while the root filesystem is mounted.
